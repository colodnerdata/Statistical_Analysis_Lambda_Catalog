# v3.4 — Model Comparison Sheet

## Context

Every v2.0 Regression sheet already exposes a fixed-height, fixed-position status block
and, since v3.3, a **unit-space headline** (`Comparison_Headline_GoF` → `$AH$6:$AH$8`:
R², Adjusted R², RMSE in original units) plus a **model-formula readout**
(`Comparison_Model_Formula`). v3.3 shipped those three as sheet-scoped named ranges
specifically so a second sheet could read them by NAME. The Model Comparison sheet is
what happens when that second sheet is allowed to.

No new modeling capability is added — this is a cross-sheet aggregation and navigation
layer, which is why it is a MINOR. Resolved designs on record: `DECISIONS.md` § v2.3
(`Model_Formula_String` name resolution; the `Comparison_*` named-range interface),
`ROADMAP.md` § v3.4, `TODOs.md` § v3.4, `MODEL_TESTING_ASSETS.md` § 2 item 1.

**Out of scope (deferred to v3.4.x, see "Scope split" below):** the Jacobian-corrected
unit-space information criteria (AIC / AICc / BIC) and unit-space PRESS / LOOCV. v3.3
deferred these (ROADMAP § v3.3: "likelihood depends on the Jacobian of the
transformation; the 'right' comparison is on the original response's likelihood"). They
are *new statistical capability* — building them breaks the "purely aggregation, no new
modeling" framing that makes v3.4 a MINOR, so they ship as a follow-up, not as a gate.

## Grounding — current state (verified against code, not just docs)

- **Shipped `Comparison_*` named ranges** (`write_sheet_regression.py:880-899`,
  `_setup_local_names`, all sheet-scoped, pinned by `tests/test_sheet_writers.py:1278-1297`):
  - `Comparison_Anchor` → `='Regression'!$AF$2` — the response-in-effect readout (AE2
    label "Predicted Variable" / AF2 value), the natural hyperlink target.
  - `Comparison_Headline_GoF` → `='Regression'!$AH$6:$AH$8` — the v3.3 unit-space triplet.
  - `Comparison_Model_Formula` → the Model Formula readout cell in the §4b
    materialization band (`regression_layout.py:_C_MODEL_FORMULA`, row 1).
  **`Comparison_Prediction_Output` does NOT exist in code** — it is named in ROADMAP §
  v3.4 and DECISIONS § v2.3 as one of "three" but was never wired. It is the v3.4 add.
- **`Model_Formula_String` is ABSENT from the catalog and all code** — it lives only in
  docs/plans. The shipped model-formula mechanism is the sheet-scoped catalog closure
  `Model_Formula()` (`lambda_functions.json:3080`, `scope: "Regression"`), which reads
  the *current* sheet's spec and cannot read another sheet. `Model_Formula_String` is the
  cross-sheet variant v3.4 needs for the registry's display text.
- **Every GoF statistic the ROADMAP lists already exists on the Regression sheet**
  (no new catalog fit-statistic work is needed to populate the table):
  - `AA5` R Square, `AA6` Adjusted R Square, `AA7` Standard Error, `AA8` Observations (n).
  - `AD4` PRESS, `AD5` PRESS R², `AD7` AIC, `AD8` BIC, `AD9` AICc.
  - ANOVA: `AE14` F, `AF14` Significance F (F p-value); `AB15` Regression df (= k −
    intercept) so k = `AB15 + Allow_Intercept`.
  - `LOOCV_Residual()` (`write_sheet_regression.py:1882`) already produces the
    leave-one-out residuals; PRESS = `SUMSQ(LOOCV residuals)`, so a LOOCV column is a
    trivial derivation if wanted.
  - The comparable-by-construction set is the v3.3 headline `AH6:AH8` (original units).
- **No "model registry" exists on a worksheet.** The production workbook has a single
  Regression-shaped sheet literally named `"Regression"` (`build_production.py:86`); the
  test-model artifact has ~47, one per case, enumerated only in the Python case-list
  (`build_test_models.py:184-185`). A registry data structure passed to a new
  `write_comparison_sheet` writer is net-new.
- **No inline sheet-level XLOOKUP exists yet.** XLOOKUP is proven inside catalog LAMBDAs
  (`Lag_By`, `Group_Mean_At`, both `if_not_found=NA()`, exact match) but no sheet cell uses
  it. v3.4 is the first inline sheet-level use — the reverse data flow (Regression sheets
  pulling shared prediction inputs FROM the Comparison sheet).

## Decisions taken this session

1. **Scope split — MINOR navigation+headline core now; unit-space IC/LOOCV deferred to
   v3.4.x.** The GoF table ships with the **comparable-by-construction** columns
   (unit-space R²/AdjR²/RMSE from the v3.3 headline) plus the **transform-invariant**
   columns (n, k, F, F p-value). The fit-space AIC/AICc/BIC/PRESS already on the sheet
   are *not* comparable across transform pairs (a Log model's likelihood is on a
   different scale than a None model's), so they are shown only within a same-transform
   subset and greyed/hidden otherwise — OR simply deferred with the unit-space versions.
   Building the Jacobian-corrected unit-space IC is new statistical capability and is the
   v3.4.x follow-up. This keeps v3.4 honestly a MINOR.
2. **The GoF table reads by NAME, extending the public interface.** Rather than spell
   cross-sheet A1 addresses (forbidden by CLAUDE.md), PR2 adds a single sheet-scoped
   `Comparison_GoF_Block` range over the stable GoF region per Regression sheet, and the
   Comparison sheet `INDEX`es into it by documented position. `Comparison_Headline_GoF`
   stays the comparable-by-construction column (read directly, as shipped). These names
   join the public-interface commitment named in the v3.4.0 changelog.
3. **The model registry is a build-time Python list, not a worksheet self-enumeration.**
   `write_comparison_sheet(book, registered_models)` takes an explicit list of
   `(sheet_name, anchor_cell)` pairs (the production workbook passes its one model; the
   test-model build passes its case list). The Comparison sheet does not scan for
   Regression-shaped sheets — the build owns the registry, matching how every other
   sheet is authored.
4. **`Model_Formula_String(anchor_cell)` is workbook-scoped, not sheet-scoped.** Unlike
   `Model_Formula()` (scope `Regression`), it must resolve *any* sheet from its anchor
   argument, so it lives at workbook scope with no `scope` field. It resolves the sheet
   from the anchor cell (no `INDIRECT` — non-volatile; per DECISIONS § v2.3), validates
   the target is a Regression sheet by a header signature, and returns `NA()` on a
   non-Regression target so a stale registry row degrades visibly rather than silently.

### PR1 — `Model_Formula_String` LAMBDA (READY · M · no Excel)

The cross-sheet model-formula assembler. No Excel needed — pure catalog + the same
pure-Python-mirror + catalog-formula-text test pattern as the v3.9 trio.

**Catalog entry** (`lambda_functions.json`, workbook-scoped, category `Model
Construction`, subcategory `Sheet-Scoped Constructors` alongside `Model_Formula`):

```
=LAMBDA(anchor,
    LET(
        sheet,  CELL("filename", anchor),     // sheet the anchor lives on
        ... resolve sheet name from filename ...
        sig,    <header-signature probe on that sheet's spec block>,
        IF(NOT(sig), NA(),
            LET(
                // read THAT sheet's spec — same assembly as Model_Formula(),
                // but every spec reference qualified to the anchor's sheet
                ...response & " ~ " & intercept & predictors & FE suffix...
            )
        )
    )
)
```

- **Anchor, not sheet name.** The argument is a cell (`Sheet2!$A$1`); the sheet is
  resolved from it. No `INDIRECT` (volatile); the anchor cell carries the sheet context
  the same way `Comparison_Anchor` does. This is the DECISIONS § v2.3 resolution.
- **Header-signature validation → `NA()`.** Probe a stable spec-block signature (e.g.
  `Spec_Role` exists on the anchor's sheet and `COLUMNS` matches `Source_Data`); on a
  non-Regression target return `NA()` so a registry row pointing at a deleted/renamed
  sheet shows `#N/A` instead of a wrong or blank formula.
- **Reuses `Model_Formula()`'s assembly logic.** Both build the string from
  `Constructed_Column_Names()`, `Allow_Intercept`, the FE count/name — but
  `Model_Formula_String` qualifies every spec reference to the anchor's sheet while
  `Model_Formula()` reads unqualified (current sheet). Consider factoring the shared
  assembly into a helper if the duplication is non-trivial; otherwise two bodies is fine
  (no import can reach a JSON string literal — the test pins the text).

**Test** (`tests/test_model_formula_string_verification.py`, modeled on
`test_categorical_model_construction_verification.py`): a pure-Python mirror of the
assembly + signature check against hand-constructed "sheet" fixtures (a dict of spec
rows), covering the Log/None response, mixed predictor transforms, FE suffix, the
no-intercept case, and the `NA()` non-Regression-target path. Implementation-shape
assertions: workbook-scoped, `CELL("filename"` present, `NA()` present, `INDIRECT`
absent.

**Docs:** DECISIONS § v2.3 already records the design; add a v3.4 section noting the
shipped signature. Bump catalog counts (151 → 152 total, 127 → 128 workbook-scoped;
sheet-scoped unchanged at 24). Rebuild `dist/Lambda_Library.xlsx` (`git add -f`).

### DECISION (gates PR2) — the `XLOOKUP [if_not_found]` fallback (OPEN · S · no Excel)

The one open decision the owner must make before the sheet work. The Comparison sheet is
the **source** of a shared "what-if" prediction-input row keyed by spec name; each
Regression sheet pulls its inputs from it via `XLOOKUP(spec_name, Comparison_Inputs,
[input_cols], [if_not_found])`. The mismatched case (M1 vs M14, different predictor sets)
is what forces the choice: when the shared row names a predictor a given model does not
have, what does that model's XLOOKUP return?

| Option | Behavior | Trade-off |
|---|---|---|
| **A — `NA()` (recommended)** | A predictor not in the model yields `#N/A` in that model's pulled inputs; the model predicts on its own predictors only and the missing column is visibly excluded. | Matches `Lag_By`/`Group_Mean_At`'s existing `if_not_found=NA()` convention (consistency); the model never silently substitutes a value. The prediction-results table then shows that model as "not evaluable on this scenario" for the missing predictor — honest. |
| B — `0` | Missing predictor defaults to 0. | Silent: a 0 is a real input that changes the prediction. Risks a wrong-number-with-no-signal bug, exactly the class CLAUDE.md warns about. |
| C — model's own default | Fall back to the Regression sheet's local input cell. | Two sources of truth; the "shared scenario drives every model" promise breaks for mismatched models. |

**Recommendation: A (`NA()`).** It is the convention the catalog already uses, it keeps
the comparison honest (a model without a predictor cannot be made to pretend), and it
makes the mismatch visible in the prediction-results table rather than hiding it. The
mismatched-predictor test asset (M1 vs M14) exists precisely to exercise this path.

### PR2 — Comparison sheet layout (READY · L · needs Excel)

Depends on PR1 (registry display text) and the decision above (XLOOKUP fallback). Needs
Excel for the hyperlink insertion and the cross-sheet XLOOKUP recalculation.

**New writer `lambda_catalog/write_sheet_comparison.py`** → `write_comparison_sheet(book,
registered_models)`, called from `build_production.py` (one model) and
`build_test_models.py` (the case list). Layout:

- **Model registry** (rows 4+): one row per `registered_models` entry —
  | Hyperlink (to `Comparison_Anchor` on that sheet) | `=Model_Formula_String(<that sheet's anchor>)` display text |. The hyperlink target is the shipped `Comparison_Anchor` ($AF$2) — a real readout cell, not a status cell that is blank when the spec is legal (B2/G2/H2/O2 are poor targets).
- **GoF table** (one column per statistic, one row per model, transposed-reads the
  block):
  - Comparable-by-construction: unit-space R² / Adj R² / RMSE — read directly from each
    sheet's `Comparison_Headline_GoF` (shipped name).
  - Transform-invariant: n (`AA8`), k (`AB15 + Allow_Intercept`), F (`AE14`), F p-value
    (`AF14`) — read from a new `Comparison_GoF_Block` sheet-scoped name over the stable
    GoF region, `INDEX`ed by documented position. No A1 spelling (CLAUDE.md).
  - Fit-space AIC/AICc/BIC/PRESS (`AD7/AD9/AD8/AD4`): present in the block; **shown
    greyed when the model's response transform differs from the scenario's reference
    model**, with a note that cross-transform IC comparison is deferred to v3.4.x. (Or
    simply omit until v3.4.x — pick at implementation; the recommendation is show-but-gate
    so the table is complete for same-transform comparisons.)
- **Shared prediction inputs** (the Comparison sheet is the SOURCE): one editable input
  row keyed by predictor name; the column header row names the union of predictors across
  registered models. This is the one editable surface on the Comparison sheet
  (`INPUT_COLOR`).
- **Prediction results table**: one row per model, pulling each model's back-transformed
  point estimate (`AL3`) and CI/PI bounds (`AL7:AL10`) from that sheet — gated by a new
  `Comparison_Prediction_Output` sheet-scoped name (the v3.4 interface add) over the
  Prediction Outputs region.
- **Reverse wiring on each Regression sheet**: its Prediction Inputs band gains an
  XLOOKUP pull from the Comparison sheet's shared input row (keyed on the model's spec
  name), with `[if_not_found]` per the decision above. Local input cells remain as the
  fallback when no Comparison sheet is present (production single-sheet demo can still
  type directly), so the Regression sheet still stands alone.

**New sheet-scoped names** (added in `_setup_local_names`, extending the public
interface): `Comparison_Prediction_Output` (over the Prediction Outputs region), and
`Comparison_GoF_Block` (over the stable GoF region). Pin both in
`tests/test_sheet_writers.py` next to the existing `Comparison_*` test. The v3.4.0
changelog names all four `Comparison_*` names explicitly (ROADMAP § v3.4's

**Sheet-name validation**: `Comparison` (or `Model Comparison` — must clear
`test_model_sheets.validate_sheet_name` and the 31-char/legal-charset/unique rules). Add
to the registry-build validation so a bad name fails in unit tests, not mid-build.

**Tests**: `tests/test_sheet_writers.py` `RecordingSheet` assertions for the registry
rows, GoF table cells, input row, and the four named ranges; `tests/test_workbook_invariants.py`
(sheet-scoped vs workbook-scoped still holds); the cross-sheet XLOOKUP evaluated in the
gated Excel integration test (see test-asset pin below). `tools/inspect_regression_sheet.py`
extended if it needs to read the new names (import the constants, never redeclare).

**Docs**: ROADMAP § v3.4 → delivered for the navigation+headline+shared-inputs halves,
open for the unit-space IC/LOOCV follow-up; TODOs § v3.4 — tick the two READY items, leave
the OPEN decision item resolved-by-reference to this plan; CLAUDE.md — note the
