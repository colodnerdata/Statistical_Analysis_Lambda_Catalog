# v3.3 — Unit-space dispatch, prediction back-transformation, model formula label

## Context

The v2.2 column-G `Log` wiring shipped a model that **fits** correctly in log space
end to end, but stops there. `Response_Column()` / `Predictor_Columns()` apply
`Ln_Positive` per spec row, `Constructed_Column_Names()` relabels a logged column
`Ln(name)`, `Constructed_Column_Transforms()` carries the per-constructed-column
`Log`/`None` flag, and the Prediction Inputs band auto-logs a raw typed value using
that flag — so the **predictor** side already handles an arbitrary mix of `Log` and
`None` correctly (`write_sheet_regression.py:1606`, `:1719`).

What is missing is everything on the **response** side. In-sample `Predicted Y`, the
residual columns and the whole Prediction Outputs block stay in log space, labelled
`(Log)`; an R² computed on `Ln(y)` is not comparable with one computed on raw `y`.
`Model_Context()` already reserves elements 3 and 4 for exactly this
(`Context_Response_Transform` / `Context_Predictor_Transform`), and
`write_sheet_regression.py:526-529` records that they "have no engine reader until
the v3.3 unit-space dispatcher".

This milestone closes that gap and, alongside it, ships the model-formula label —
needed here to head the unit-space block, and needed again by v3.4 Model Comparison.

Resolved designs already on record: `DECISIONS.md` § v2.2 (unit-space dispatcher;
Duan smearing with a per-cell `Back_Transform_Method` toggle), § v2.3
(`Model_Formula_String`, the `Comparison_*` named ranges), `ROADMAP.md` § v3.3,
`TODOs.md` § v3.3.

**Out of scope:** the standalone transform library remainder (`Center`, `Zscore`,
`Winsorize`, …). v3.3 stays open in ROADMAP/TODOs for that half.

## Decisions taken this session

1. Ship all three: unit-space dispatcher, Duan back-transformation, model formula label.
2. The `Back_Transform_Method` toggle drives **both** the displayed predictions and the
   unit-space GoF numbers — via an appended optional `[Method]` argument defaulting to
   `Duan`, so unit-space R² always corresponds to the predictions the sheet shows.
3. Back-transformed counterparts for the Prediction Outputs block, a `Predicted Y
   (Original Units)` column and a `Residual (Original Units)` column.
4. The model formula is a **sheet-local formula cell**, not the anchor-cell
   `Model_Formula_String` LAMBDA. v3.4 reads the cell.

## Amendments to the recorded design (record these in DECISIONS.md)

- **The transform pair comes from `[Context]`, not from two positional arguments.**
  The v2.2 resolution wrote `Unit_Space_R_Squared(model, response_transform,
  predictor_transform)`; that predates the v3.0 context array, which already carries
  both. Passing them again would be a second source of truth. Signature becomes
  `Unit_Space_R_Squared(X, Y, Y_Full, [Include], [Context], [Method])`, dispatching on
  `Context_Response_Transform` / `Context_Predictor_Transform`. This is the reader
  elements 3–4 were reserved for.
- **`Y_Full` is `Response_Column()`** — transformed but *not* demeaned — passed
  alongside `Y` = `Design_Response()` (transformed *and* demeaned). Their difference
  on the filtered sample is exactly the level the within transformation removed, so
  the full-space fitted value is `Predictions(X,Y,Include) + (Y_Full − Y)`. This is
  what makes Fixed Effects + Log work without a `Group_Mean` call, an FE-detection
  branch or a new closure — the level shift is zero whenever no FE row is declared.
- **The pair-SWITCH lives in `Unit_Space_Predictions` / `Back_Transform_Response`,
  not repeated in each GoF name.** The transform pair changes the *arithmetic* only at
  the back-transformation step; R², Adjusted R² and RMSE are ordinary per-statistic
  names over the back-transformed fitted values. Keeps the `Unit_Space_*` names the
  ARCHITECTURE § 1 departure records, confines the combinatorial dispatch to one place.
- **The recognised pairs are `{None, Log} × {None, Log, Mixed}` — six, not four.**
  The v2.2 text says "four possible combinations", written before
  `_PREDICTOR_TRANSFORM_FORMULA` gained its `Mixed` value
  (`write_sheet_regression.py:497-507`). Without a `Mixed` branch a spec with one
  logged and one unlogged predictor falls through to `NA()`. Anything outside the six
  is `NA()`. Record honestly that the predictor half of the pair is **inert** for these
  three statistics — a response-unit statistic cannot depend on predictor units — so it
  is carried as *validation*, not as a computation input.
- **CI/PI bounds are back-transformed with `EXP` alone, never smeared.** A monotone
  transform preserves coverage: `P(L ≤ ln y ≤ U) = P(e^L ≤ y ≤ e^U)`. Multiplying both
  bounds by the smearing factor would destroy it. Consequence the caveat row must state:
  under `Duan` the point estimate (conditional **mean**) does not sit at the centre of
  the interval, whose ends bracket the conditional **median**.
- **Under FE + Log the unit-space statistics are *total*, not *within*.** `exp()` of a
  within deviation predicts nothing, so the back-transformed fitted value necessarily
  carries the group effect and `SST_unit` is taken about the grand mean of raw `y`. Every
  other statistic on the sheet reports the within flavour; this one cannot. State it on
  the block's cell note. With `Transform = None` the dispatchers return the ordinary
  statistic verbatim, so the within convention is untouched there.
- **`Back-Transformation` was filed as a subcategory under `Model Construction`, not
  promoted to top-level.** The seven names (`Smearing_Factor`, `Back_Transform_Response`,
  `Unit_Space_Predictions`, `Unit_Space_Observed`, `Unit_Space_Residuals`, and the three
  `Unit_Space_*` GoF names) are wired as `subcategory: "Back-Transformation"` inside
  `category: "Model Construction"`. Promoting `Back-Transformation` to its own top-level
  category would have created a second one alongside `Distribution Fitting` (which has one
  function) with no apparent gain — the v3.3 plan deferred the choice to the ARCHITECTURE
  § 2 "promote at 2+ functions" rule and that rule gave "stay nested" here.

## Work

### 1. Catalog functions — `lambda_functions.json` (all `scope: "workbook"`)

New category/subcategory: `Model Construction` → `Back-Transformation` (or a new
top-level `Back-Transformation`; follow the ARCHITECTURE § 2 "promote at 2+ functions"
rule). None of these name a worksheet, so `sync_workbook_names` writes them into both
artifacts — unlike `Base_Period_Delta`.

| Function | Shape |
|---|---|
| `Smearing_Factor(X, Y, [Include], [Context])` | scalar. `1` when the response transform is `None`; `AVERAGE(EXP(Residuals(X,Y,Include)))` when `Log`; `NA()` otherwise. Returning `1` rather than `NA()` on `None` is what lets the sheet's cells stay uniform. |
| `Back_Transform_Response(Values, [Context], [Method], [Smearing])` | elementwise. `None` → `Values` unchanged. `Log` + `Duan` → `EXP(Values) * Smearing`. `Log` + `Naive` → `EXP(Values)`. Unrecognised transform or method → `NA()`. `[Method]` defaults `"Duan"`, `[Smearing]` defaults `1`. |
| `Unit_Space_Predictions(X, Y, Y_Full, [Include], [Context], [Method])` | n×1. `SWITCH` on the six recognised `(response, predictor)` pairs; each branch back-transforms `Predictions(X,Y,Include) + (FILTER(Y_Full,Include) − FILTER(Y,Include))`. Computes its own smearing factor. |
| `Unit_Space_Residuals(X, Y, Y_Full, [Include], [Context], [Method])` | n×1. Observed response in original units minus `Unit_Space_Predictions`. |
| `Unit_Space_R_Squared(X, Y, Y_Full, [Include], [Context], [Method])` | `1 − SSE_unit/SST_unit`; `SST_unit` about the mean with an intercept (`Context_Has_Intercept`), about zero without — mirroring `SS_Total`. May go negative; that is honest, do not clamp. |
| `Unit_Space_Adjusted_R_Squared(...)` | `1 − (1 − R²_unit) · Total_Degrees_Of_Freedom / Residual_Degrees_Of_Freedom`, reusing the existing df functions so `Context_DF_Absorbed` is honoured. |
| `Unit_Space_RMSE(...)` | `SQRT(SSE_unit / Residual_Degrees_Of_Freedom(...))` — the same divisor `SE_Regression` uses, so the `None` case reduces to it exactly. |

**The reduction invariant is the acceptance criterion:** with `Transform = None`
everywhere, `Unit_Space_R_Squared ≡ R_Squared`, `Unit_Space_Adjusted_R_Squared ≡
Adjusted_R_Squared`, `Unit_Space_RMSE ≡ SE_Regression`, and the two new residual
columns equal `Predicted Y` / `Residuals`. Same non-breaking property v2.2 established.

Each entry needs the full schema fields (`catalog_schema.py:265-385`): `name`,
`category`, `subcategory`, `number_format`, `formula_display`, `arguments`, `yields`,
`description`, `plain_language_summary`, `notes`, `test_table`. Follow `Ln_Positive`
as the model entry.

**Prediction Outputs — original-units column in `AL`.** `AL` is free above row 17.
`AL2` sub-header `"Original Units"` (and `AK2` `"Fit Space"`); `AL3` point estimate via

amendment above). `AL4:AL6` stay blank: SE and t-critical have no unit-space counterpart.

**Caveat row** at `AJ15:AL15` (the one free row between the Group Count readout at 14
and `PREDICTION INPUTS` at 16), merged and wrapped: *Duan = Duan (1983) smearing —
estimates the conditional mean. Naive = textbook EXP(ŷ) — the conditional median,
biased for the mean. CI/PI bounds are back-transformed with EXP alone, so under Duan
the point estimate does not sit at the interval's centre.*

**Residual Output zone — two new columns.** Append after `_C_AY` rather than inserting,
so no existing `_C_*` constant has to be renamed away from its own column letter:

- `_C_AZ = 52` — `Predicted Y (Original Units)`, `=Unit_Space_Predictions(…)`
- `_C_BA = 53` — `Residual (Original Units)`, `=Unit_Space_Residuals(…)`
- the gutter/chart-anchor constant currently named `_C_AZ` becomes `_C_BB = 54`
- `_ZONES` last entry `(40, 51)` → `(40, 53)`

`_C_CHART_LABEL_NAME` … `_LAST_CHART_COLUMN` and the whole § 4b materialization band
already derive from that gutter constant, so the charts, Model Context, `Sample_Include`
and design-matrix zones shift right automatically. `_GAP_COLUMNS` is derived from
`_ZONES` and re-asserts one-wide. Both new headers join the `(Log)`-suffix loop's
**non**-suffixed set — they are in original units by construction, so a `(Log)` suffix
would be a lie; give them the FE `(Within …)` suffix treatment only if the response is
untransformed. Simplest correct rule: they carry no conditional suffix at all.

**Diagnostic charts keep reading the log-space columns.** The OLS assumptions live in
fit space; nothing in `_write_diagnostic_charts` or `_setup_local_names` changes.

### 3. Model formula label

`AA2` label `"Model Formula"` (bold), `AB2` the string (overflows the empty `AC2:AD2`).
Built entirely from existing pieces — `_RESPONSE_NAME_FORMULA`,
`_RESPONSE_LOG_FORMULA`, `Allow_Intercept`, `Constructed_Column_Names()`,
`_FIXED_EFFECTS_COUNT_FORMULA` / `_FIXED_EFFECTS_NAME_FORMULA` (all already imported at
`write_sheet_regression.py:116-117`):

```
Ln(Unit_Cost_BY) ~ 1 + Ln(Cumulative_Units) + Experience_Stock + Origin[Europe] | Facility
```

`Constructed_Column_Names()` already emits `Ln(name)` per logged predictor, level-qualified
dummy names and `left × right` interaction names, so **the mixed Log/None predictor case
renders correctly with no extra work** — that is the whole reason to build the label from
the constructor twin rather than from the spec rows. `TEXTJOIN(" + ", TRUE, …)`, `"1"`
prepended when `Allow_Intercept`, `" | " & <FE name>` appended when an FE row is declared.
