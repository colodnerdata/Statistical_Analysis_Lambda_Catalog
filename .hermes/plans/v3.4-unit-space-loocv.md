# Unit-space LOOCV — residual spill, RMSE, MAE, and a named smearing treatment

## Context

v3.3 shipped the unit-space / back-transformation family: `Smearing_Factor`,
`Back_Transform_Response`, `Unit_Space_Observed/Predictions/Residuals`, and the three
in-sample goodness-of-fit statistics (`Unit_Space_R_Squared`,
`Unit_Space_Adjusted_R_Squared`, `Unit_Space_RMSE`), surfaced in the **UNIT-SPACE FIT**
block at `AG3:AH9` with a Duan / Naive toggle at `AH4`.

Cross-validation was left in fit space. `LOOCV_Residual`, `LOOCV_Prediction`, `PRESS` and
`Hat_Diagonal` all exist and are wired (column `AX` "PRESS Residual"; `AE4`/`AE5`
PRESS / PRESS R²) — but every one of them reports in the space the model was *fitted*
in. On a Log-response model that is log units, which is not the space anyone makes a
decision in. `.hermes/plans/v3.4-model-comparison-sheet.md:8-13` records the deferral
explicitly ("unit-space PRESS / LOOCV … ship as a follow-up"), and ROADMAP § v3.3
lists only R² / Adj R² / RMSE as having unit-space counterparts.

This change closes that gap: an out-of-sample residual column and two out-of-sample
error scalars, all in original units, plus the thing that makes them honest — a
**visible statement of how the smearing factor was obtained**. Under Duan, the LOO
residual for row *i* is back-transformed with a smearing factor estimated from *all n*
in-sample residuals, row *i* included. That is a real (small) leakage. Naming it on the
sheet is what separates "we approximated" from "we didn't notice", and it gives the
eventual fold-specific implementation a slot to land in rather than a silent change of
meaning.

## Decisions taken

| Question | Answer |
|---|---|
| `Unit_Space_LOOCV_RMSE` divisor | **n** — `√(Σr²_loo / n)`. Every LOO prediction is genuinely out-of-sample, so no df are consumed; `MAE` averages over the same n, so the pair reads consistently. |
| Layout | **A new boxed sub-block at `AG10:AH13`.** Rows 3–9 stay byte-identical, `Comparison_Headline_GoF` (`$AH$6:$AH$8`) is untouched, and the qualification is unambiguously scoped to the out-of-sample pair it caveats. |
| PR shape | **Four-rule items 1–3** (feature + oracle + test-model case + headless tests + docs). Item 4, the `excel-only-runs/` transcript, needs Excel and ships in a follow-up commit from a Windows machine. |

### Flagged, not changed: `Unit_Space_RMSE`'s divisor

You noted `Unit_Space_RMSE` may also be wrong. It is `√(SSE_unit / df_residual)`, and the
critique is fair on its face: the label says RMSE (÷ n) and the formula is a standard
error of the regression (÷ n−p); and once the response has been back-transformed, `n−p`
buys no unbiasedness anyway, because SSE_unit is not the residual sum of squares of a
linear fit in that space.

It is nonetheless **deliberate**, not a slip. `docs/DECISIONS.md:2934-2939` makes the
reduction invariant the milestone's acceptance criterion — with `Transform = None`
everywhere, `Unit_Space_RMSE ≡ SE_Regression` *exactly* — and `tests/test_unit_space_dispatch.py:342`
pins the shared divisor. Changing it breaks that invariant, the shipped v3.3 changelog
text, and the `Comparison_Headline_GoF` contract v3.4 is being designed against.

**This plan does not change the formula.** In scope instead: relabel `AG8` from
`"RMSE (Unit)"` to `"SE Regression (Unit)"` and add a hover Note stating the divisor, so
the label stops promising `÷ n` while `LOOCV RMSE (Unit)` one row below genuinely
delivers it. A formula change is a separate, breaking PR; it gets an OPEN item in
`docs/TODOs.md` with this analysis, not a silent edit here.

## Step 1 — Four new catalog functions

`lambda_functions.json`, appended after `Unit_Space_RMSE` (currently the last entry),
`category: "Model Construction"`, `subcategory: "Back-Transformation"`, workbook scope
(no `scope` key). Document order is install order, and each depends only on entries
above it.

**`Unit_Space_LOOCV_Residual(X, Y, Y_Full, [Include], [Context], [Method])`** → n×1 spill.
Same signature and same `Y`/`Y_Full` contract as `Unit_Space_Residuals`. It is
`Unit_Space_Predictions` with `LOOCV_Prediction` substituted for `Predictions`:

```excel
=LAMBDA(X, Y, Y_Full, [Include], [Context], [Method],
  LET(
    context_arg, IF(ISOMITTED(Context), Model_Context(), Context),
    filt_arg,    IF(ISOMITTED(Include), TRUE, Include),
    method_arg,  IF(ISOMITTED(Method), "Duan", Method),
    rt,          Context_Response_Transform(context_arg),
    pt,          Context_Predictor_Transform(context_arg),
    sm,          Smearing_Factor(X, Y, filt_arg, context_arg),
    shift,       IF(rt = "Log", FILTER(Y_Full, filt_arg) - FILTER(Y, filt_arg), 0),
    loo_fit,     IFERROR(LOOCV_Prediction(X, Y, filt_arg) + shift, NA()),
    y_unit,      Unit_Space_Observed(Y, Y_Full, filt_arg, context_arg),
    r_loo,       y_unit - Back_Transform_Response(loo_fit, context_arg, method_arg, sm),
    SWITCH(rt & "|" & pt,
      "None|None", r_loo, "None|Log", r_loo, "None|Mixed", r_loo,
      "Log|None",  r_loo, "Log|Log",  r_loo, "Log|Mixed",  r_loo,
      NA())
  )
)
```

Three load-bearing details, each inherited from an existing function rather than invented:

* the `shift` is gated on `rt = "Log"` and bound exactly as in `Unit_Space_Predictions`
  (`DECISIONS.md:2822-2841` — applying it unconditionally turns the within-flavoured
  statistics into total ones, a wrong number that still looks plausible);
* the observed side comes from `Unit_Space_Observed`, never from `Y_Full` directly
  (`DECISIONS.md:2843-2860` — that shortcut produced R² = −148.66 against a true 0.693);
* `LOOCV_Prediction` carries **no** error guard of its own, so `h_i = 1` yields
  `#DIV/0!`. The `IFERROR(…, NA())` is elementwise and mirrors `LOOCV_Residual`'s own
  `IFERROR(e / (1 - h), NA())` — `#N/A` on that row, not `#DIV/0!`.

The six-arm `SWITCH` gate is repeated here rather than delegated because there is no
`Unit_Space_*` function to delegate the LOO fitted vector to; `tests/test_unit_space_dispatch.py:283`
already pattern-checks that shape across the family.

**`Unit_Space_LOOCV_RMSE(X, Y, Y_Full, [Include], [Context], [Method])`** → scalar:

```excel
    r, Unit_Space_LOOCV_Residual(X, Y, Y_Full, filt_arg, context_arg, method_arg),
    IFERROR(SQRT(SUMSQ(r) / ROWS(r)), NA())
```

`ROWS(r)`, not `COUNT(r)`: an `#N/A` row propagates through `SUMSQ` regardless (the same
behaviour `PRESS` has), so the divisor is plainly the sample size the fit used.

**`Unit_Space_LOOCV_MAE(...)`** → scalar: `IFERROR(AVERAGE(ABS(r)), NA())`, same `r`.

**`Smearing_Treatment([Context], [Method])`** → text scalar. Pure function of
(response transform, method); takes both as arguments, so it is sheet-agnostic and
workbook-scoped:

```excel
=LAMBDA([Context], [Method],
  LET(
    context_arg, IF(ISOMITTED(Context), Model_Context(), Context),
    method_arg,  IF(ISOMITTED(Method), "Duan", Method),
    rt,          Context_Response_Transform(context_arg),
    IF(rt = "None", "n/a — no back-transform",
      IF(rt = "Log",
        SWITCH(method_arg,
          "Naive", "Naive (no smearing)",
          "Duan",  "Full-sample Duan (approx.)",
          NA()),
        NA()))
  )
)
```

The `SWITCH` is the extension point: fold-specific Duan arrives as a fourth arm plus a
third item on `AH4`'s validation list, with no restructuring. Say so in `description`.
Text is kept short because `AH` is 16 wide — the full explanation of *what* is
approximated goes in the hover Note on the `AG13` label, following the sheet's
status-cell convention (short message in-cell, guidance on hover).

**Also required by `tests/test_doc_catalog_counts.py`:** bump the catalog counts
151 → 155 (and workbook-scoped 127 → 131) in `README.md`, `CONTRIBUTING.md`, and
`docs/ROADMAP.md`.

## Step 4 — The NumPy oracle

`lambda_catalog/regression_shared.py` — `RegressionUnitSpace` gains
`loocv_residuals_unit: tuple[float, ...]`, `loocv_rmse_unit: float`,
`loocv_mae_unit: float`, `smearing_treatment: str`.

`lambda_catalog/analyze_regression_sheet.py`, inside the unit-space block of
`calculate_regression_results_from_matrix` (`:590-738`) — the leverage vector and
residuals are already in scope from the residual section, so this is four lines placed
right after `residuals_unit` is computed (`:663`):

```python
loo_fit_space = predictions - h * e / (1.0 - h) + level_shift
# back-transform through the SAME Duan/Naive branch chosen above
loocv_predictions_unit = (np.exp(loo_fit_space) * smear_or_1) if log else loo_fit_space
loocv_residuals_unit = y_unit - loocv_predictions_unit
loocv_rmse_unit = sqrt(float(np.sum(loocv_residuals_unit ** 2)) / n)
loocv_mae_unit = float(np.mean(np.abs(loocv_residuals_unit)))
```

with `smearing_treatment` derived from `(response_transform, back_transform)` by the same
three-way rule as the LAMBDA. Keep the existing discipline: an unrecognised
`back_transform` **raises** (`:655-662`) rather than defaulting to Duan.
